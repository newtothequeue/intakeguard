# ADR 0007: Spec 0.1.4. In-house legacy PDF decoders; idempotence within maxBytes

**Status:** Accepted. Owner decisions, 2026-11-22.

## Context
1. The fuzzer (PR #7) found a contradiction in spec 0.1.2: `maxBytes` limits only the input, *and*
   re-sanitizing an output is never rejected. An output larger than `maxBytes` can't satisfy both.
2. The reviewer found (pre-existing) that content streams using ASCII85, ASCIIHex, RunLength or LZW (alone or
   chained with Flate) were `accepted` with `pdf.hidden-content` `skipped`. That violates "`accepted` means every
   applicable check passed". Object streams with these filters were rejected, so there was no active-content bypass.

## Decisions
1. **Narrow the idempotence promise:** it holds for outputs within `maxBytes`. A larger output is rejected on a
   second pass with `LIMIT_BYTES_EXCEEDED`, which is expected. No new reason code.
2. **Add in-house decoders** for ASCIIHex, ASCII85, RunLength and LZW (EarlyChange 0/1, predictors), with **no new
   dependency**. They apply to content, object and xref streams, chained in any order, with every byte counted
   against `maxDecompressedBytes`.
3. **Fail closed for anything still undecodable** in a stream a check depends on: `rejected`
   (`UNSUPPORTED_FEATURE`), never `accepted` with a skipped check.

Rejected alternative: reject every PDF that uses these encodings. They are rare in modern PDFs but common in old
archives and scans, so rejecting them would cause false positives for a lead RAG use case.

## Fixtures
Hidden text under each encoding and under a chain (it must be *detected*, which proves the decoders produce real
bytes) · a plain LZW false-positive guard · JS in ASCIIHex- and LZW-encoded object streams (must be
`PDF_ACTIVE_CONTENT`, not just `UNSUPPORTED_FEATURE`) · a RunLength expansion bomb
(`LIMIT_DECOMPRESSED_BYTES_EXCEEDED`) · an invalid ASCII85 stream (`STRUCTURE_MALFORMED`).
Expected outcomes are cross-checked against qpdf, which decodes all four filters.

## Consequences
The builder implements the decoders, adds them to the fuzz targets, and removes the harness exemption for
oversized outputs, replacing it with the narrowed rule.
