# ADR 0008: Spec 0.1.5. No data after a filter's end-of-data marker

**Status:** Accepted. Owner decision, 2026-11-22.

## Context
A differential battery against qpdf (4,500 PDFs with random filter chains, 35% corrupted;
`tools/differential/filters_vs_qpdf.py`) found 8 corrupted files that the engine accepted without the hidden-text
warning while qpdf decoded hidden text from them. Root cause: **qpdf's RunLength decoder ignores an early EOD
byte and keeps decoding**, while the engine stops at EOD as the PDF spec says. For the other filters qpdf and the
engine agree (both ignore trailing data), but other readers may not. Object streams were not affected: an early
EOD truncates them and they are rejected.

## Decision
Any non-whitespace byte after a filter stage's end-of-data marker makes the stream `STRUCTURE_MALFORMED`, for
every filter that has one (ASCII85, ASCIIHex, RunLength, LZW, Flate). PDF whitespace after the marker stays
allowed, because trailing EOLs after Flate data are common in real files.

## Fixtures
For each filter, hidden text placed *after* the EOD marker → `rejected` `STRUCTURE_MALFORMED`. For each filter,
only whitespace after EOD → `accepted` (false-positive guard). Plus the qpdf-differential case itself: an early
RunLength EOD with hidden text after it.

## Consequences
The builder implements the check and re-runs `realworld.py`; the reviewer re-runs the differential battery,
which should report 0 misses.

## Correction (reviewer, 2026-11-22)
The Context above overstated how often the bug showed up. The "8 corrupted files" came from a naive oracle that
matched the bytes `3 Tr` anywhere in qpdf's output. Re-analysis with a content tokenizer (`3 Tr` only as a real
operator, outside strings) showed that **1 of the 8 was a real miss**; in the other 7, `3 Tr` sat inside an
unclosed `(` string as visible characters. The qpdf RunLength early-EOD differential itself is real, demonstrated
by construction (`pdf-after-eod-runlength*`, which qpdf decodes past EOD), so the decision stands. The one real
random miss turned out to have a different cause (an unterminated hex string; see ADR 0009).
`filters_vs_qpdf.py` now uses the tokenizer oracle.
