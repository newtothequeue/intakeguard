# ADR 0004: Spec 0.1.2. Image semantics, builder rules, and independent review findings

**Status:** Accepted. Owner decisions, 2026-11-21.

## Context
PR #2 added decode-reencode and raised spec questions. An independent review
(`docs/conformance/review-pr2.md`) found two false positives (grayscale JPEG, tagged-PDF StructElem `/A`)
and an iCCP inflation bomb. Both are already covered by fixtures on `redteam/pr2-review`.

## Decisions
| # | Decision | Rationale |
|---|---|---|
| 1 | **Runtime: native Rust** (ADR 0002 accepted) | Measured results plus the independent review; WASM stays possible later from the same core |
| 2 | **Colour: drop the ICC profile, treat pixels as sRGB, no colour management library** | RAG pipelines don't need colour accuracy. Being honest in the spec text is cheaper than a new dependency that parses untrusted input |
| 3 | **Lossy WebP → JPEG q90** by default | A lossless re-encode of a lossy source was 13–30× larger |
| 4 | **Pixel buffers are governed by `maxImagePixels`, not `maxDecompressedBytes`** | Images of 35–40 MP were rejected under the default limits; the two budgets measure different things |
| 5 | **Apply EXIF orientation** (`images.applyOrientation`, default true) | Otherwise sanitized phone photos come out sideways |
| 6 | **Idempotence = a second sanitize is never rejected and finds no metadata** | JPEG gives transformed and PNG gives accepted on the second pass; both are fine |
| 7 | **Codec time overrun is documented**, not fixed | Codecs can't be interrupted; the overrun is bounded by one codec call. Use a worker process for hard deadlines |
| 8 | **Builder rules adopted as spec text**: objects not covered by any xref (including after the final `%%EOF`) → malformed; non-standard stream filters → unsupported | Both fail closed and already have fixtures |
| 9 | **`maxBytes` limits the input only** | Output size is a property of the transform, not of the attack surface |
| 10 | **Image codec crates approved**: `png 0.17`, `zune-jpeg 0.4`, `jpeg-encoder 0.6`, `image-webp 0.2` | The owner confirmed directly on 2026-11-21, after the independent review found header checks run before decoding, the iCCP bomb skipped, and no metadata leaks. (An earlier note in PR #2's Cargo.toml claimed approval before the owner had given it.) |

## Fixtures added for 0.1.2
`benign-webp-lossy-to-jpeg` (output must be `image/jpeg`), `img-exif-orientation-6` (16×8 in → 8×16 out),
`benign-png-36mp` (36 MP within the 40 MP limit → must be transformed, not rejected).
Manifest schema: `expected.outputMime` and `expected.outputDimensions`.

## Consequences
The builder implements these on top of PR #2. The engine must pass every fixture on `spec/v0.1.2`
with `--gate` before PR #2 merges.
