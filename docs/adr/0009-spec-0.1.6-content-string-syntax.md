# ADR 0009: Spec 0.1.6. Malformed strings in content streams are rejected

**Status:** Accepted (maintainer decision, 2026-11-22). The spec text and fixtures land together with the engine change in the next release, so the conformance gate stays green until then.

## Context
The one real miss in the PR #8 differential battery (see the correction in ADR 0008) was a content stream holding
`<\x82…`, an **unterminated hex string with non-hex bytes**. IntakeGuard's content scanner reads a hex string up to
the next `>`, so it never saw the hidden instruction after it, and accepted the file with no warning.
**pdfminer, used by `unstructured` and LangChain's PDFMiner loader, ends the hex string at the first non-hex byte
and extracts the hidden instruction into the pipeline.** pypdf raises an error; PyMuPDF stops at the syntax error.

A survey of nine content-syntax errors against IntakeGuard, pdfminer, pypdf and PyMuPDF found that only hex strings
with non-hex bytes (closed or not) produce the "an extractor sees hidden text, IntakeGuard is silent" outcome. Stray
`)`, `>`, `]`, `>>` and unclosed `[` or `<<` don't. An unclosed `(` produces no extractor disagreement today, but it
is lexically invalid and was measured at zero in real files, so it is included as a fail-closed measure.

## False-positive measurement (before adoption)
A strict lexer (comments, nested and escaped literal strings, dict openers, inline-image data skipped from `ID` to
`EI`) was run over every page of every readable PDF in the review environment: **563 PDFs, 8,936 pages, 0 files
with any of the three errors.** Caveat: that set is dominated by pdfTeX output. The owner's own files
(`make realworld`) remain the stronger test, and the rule should be re-measured on them.

## Decision
Page and form-XObject content: non-hex bytes in a hex string, an unclosed hex string, or an unclosed literal
string → `STRUCTURE_MALFORMED`. Inline image data is exempt.

## Fixtures
Attack cases (hidden text after the error, in page content and in a form XObject) must be `rejected`. False-positive
guards (hex strings with whitespace; an inline image whose binary data contains `<` and `(`) must be `accepted`.
